# Cloudflare feasibility for the personal encrypted-library pilot

Research date: 23 October 2026. Follow-up to [Research encrypted-library hosting within the US$10 personal-pilot budget](https://github.com/A3R0-01/Cloud-Epub/issues/20), answering [Validate Cloudflare runtime, spending controls, and retention for the personal pilot](https://github.com/A3R0-01/Cloud-Epub/issues/22). This is documentary research and source inspection, not measured runtime validation, architecture adoption, implementation, or provisioning.

## Finding

Workers + D1 + private R2 remains a technically plausible direction for the small pilot. Published base usage can remain around $5/month before tax on Workers Paid, or $0 on Free, under the earlier workload assumptions. **No verified documented combination establishes both the US$10 total ceiling and continued essential authentication, recovery, status and deletion operations after allowances are exhausted.** Paid requests remain metered even when application transfers are paused; Free limits stop requests/queries that essential operations also require. This finding does not prove every possible application-level bounding scheme impossible. It means the preferred architecture remains conditional on unresolved spending, security, availability and retention evidence. [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [budget alerts](https://developers.cloudflare.com/billing/manage/budget-alerts/).

Provider retention is a separate unresolved gate. Application-visible Workers/R2 log products can have retention within seven days, but Cloudflare's control-plane audit logs last 18 months and its DPA specifies twelve-month processing-infrastructure access logs. Those records have different purposes and contents; neither should silently be classified as an exempt record or as an ordinary Cloud EPUB request log. Evidence needed to validate per-account deletion and backup expiry remains incomplete; provider physical-erasure bounds are not established. The accepted product policy does not promise instantaneous global or forensic erasure. [Audit Logs v2](https://developers.cloudflare.com/fundamentals/account/account-security/audit-logs/), [Cloudflare DPA](https://www.cloudflare.com/cloudflare-customer-dpa/).

## Confirmed inputs and decision ownership

Use the [latest architecture inputs](https://github.com/A3R0-01/Cloud-Epub/issues/8#issuecomment-6373844085) and the confirmed [registration/quota rules](https://github.com/A3R0-01/Cloud-Epub/issues/21#issuecomment-6373698109) and [Administrator/security/suspension rules](https://github.com/A3R0-01/Cloud-Epub/issues/21#issuecomment-6373874328). The pilot is one person and one Android device. Default Storage limit is **1 GB = 1,000,000,000 bytes**, with explicit Administrator changes subject to service capacity and the unchanged US$10 total monthly ceiling. Current encrypted EPUBs, covers and library metadata plus unfinished-upload reservations consume allowance; service backups and dictionary packs are separate service costs. The former 5 GB requirement is superseded.

Android owns plaintext processing, library secrets and encryption. The backend holds operational relational state and ciphertext. The separate security decision owns authentication, cryptographic protocols, key envelopes, duplicate fingerprints and privileged recovery. Runtime convenience cannot select a weaker replacement protocol. The Admin panel has one Administrator, separate password/second-factor sign-in and recovery, and a 15-minute idle session timeout; it exposes no library plaintext. Minimal request/security logs have a seven-day maximum; there is no dedicated administrative action-history feature.

Administrative suspension revokes Cloud sessions and blocks library transfers/synchronization while preserving authentication/recovery and suspension-status access. Transfer pauses must leave essential operations and deletion processing available. Exact in-flight behavior remains with the administration discussion. Accepted recovery is nightly backups with seven daily recovery points and up to 24 hours of lost cloud changes. Library backups must disappear within 30 days of permanent account deletion; minimal opaque deletion records, including copies/history, last at most 60 days. Restores must filter permanently deleted accounts. These are product inputs, not provider promises.

## Language, runtime and cryptographic-library constraints

| Candidate | Evidence and implication |
| --- | --- |
| JavaScript / TypeScript | Both are directly supported. They expose Worker bindings without an additional language bridge; TypeScript is a plausible low-friction candidate, not a selected stack. [Languages](https://developers.cloudflare.com/workers/languages/). |
| Rust / Wasm | Cloudflare's `workers-rs` targets `wasm32-unknown-unknown`; this is not an ordinary Linux Rust process. Check each dependency's Wasm target, randomness, threading and I/O assumptions. The SDK manifest uses `wasm-bindgen`, `worker-sys`, and an explicit `d1` feature. [Rust guide](https://developers.cloudflare.com/workers/languages/rust/), [SDK manifest](https://github.com/cloudflare/workers-rs/blob/main/worker/Cargo.toml). |
| Python | Python Workers support pure Python, PyEmscripten packages and packages included in Pyodide. An arbitrary native CPython wheel is not evidence of deployability. Confirm the exact package/wheel and API bridge. [Supported packages](https://developers.cloudflare.com/workers/languages/python/packages/). |

Node compatibility is substantial but is not a Node operating-system process. For compatibility dates on/after **2026-08-04**, Node compatibility is enabled by default; older configurations need the documented flags. Some imports are polyfills whose methods do nothing or throw, so successful bundling does not prove a dependency works. Pin and test the compatibility date and exact package versions. [Node compatibility](https://developers.cloudflare.com/workers/runtime-apis/nodejs/).

Specific current capabilities matter: `node:fs` has a memory-backed virtual filesystem with read-only bundle files and temporary storage, not persistent server disk. `node:http` supports server adapters, but the `listen` port is a routing key; client methods wrap `fetch` and some socket/options behavior differs. `process.env` has Worker-specific behavior and can expose configured secrets. Do not assume an old claim that all fs/http support is absent, or assume ordinary local-server lifecycle behavior. [fs](https://developers.cloudflare.com/workers/runtime-apis/nodejs/fs/), [http](https://developers.cloudflare.com/workers/runtime-apis/nodejs/http/), [process](https://developers.cloudflare.com/workers/runtime-apis/nodejs/process/).

Source inspection at workerd commit `721cbdbf0a3f8aee2a8f23978b32731a354a5994` shows `process.dlopen` and `child_process.spawn` throwing an unimplemented-method error. Native Node addons and a helper executable therefore cannot be assumed usable; investigate a supported runtime/Wasm implementation instead. This source snapshot does not prove which workerd build Cloudflare currently deploys. [process source](https://github.com/cloudflare/workerd/blob/721cbdbf0a3f8aee2a8f23978b32731a354a5994/src/node/internal/public_process.ts), [child-process source](https://github.com/cloudflare/workerd/blob/721cbdbf0a3f8aee2a8f23978b32731a354a5994/src/node/child_process.ts).

Workers provides Web Crypto, with an explicitly documented algorithm surface. Its current `node:crypto` documentation excludes `argon2`/`argon2Sync`, DSA/DH key-pair generation, `ed448`/`x448`, and other listed exceptions. This is a compatibility constraint, not permission to select a password derivation/authentication protocol here. The security decision must identify Android/backend libraries and vectors, distinguish client and server work, and measure CPU, memory and side effects for their real parameters. [Web Crypto](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/), [Node crypto exceptions](https://developers.cloudflare.com/workers/runtime-apis/nodejs/crypto/).

The current documented resource limits are **128 MB per isolate**, including Wasm allocations and concurrent requests; **10 ms CPU/invocation on Free**, versus Paid's configurable limit (30 seconds default, 5 minutes maximum for HTTP); and **64 MiB uncompressed Worker bundle size** on both plans, without a compressed-size limit. A Free/Pro Cloudflare zone allows **100 MB request bodies**, independently of Workers Paid. Response bodies have no enforced size limit; individual Static Assets files are **25 MiB**. Streaming is necessary to avoid whole-file buffering, but does not remove incoming request limits. [Workers limits](https://developers.cloudflare.com/workers/platform/limits/).

## Private object transfers, pause and revocation

R2 buckets are private by default. Library buckets must not acquire an unprotected `r2.dev` or public custom-domain path. A Worker binding can read R2 objects as a `ReadableStream` and accept streamed writes; downloads can therefore authenticate and authorize before streaming ciphertext. Authorization still belongs to the application. Avoid exposing original book titles in object keys, headers or URLs. [Public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/), [R2 Worker API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/).

Multipart uploads through a Worker permit larger total objects while keeping each part under the Worker body limit. R2 requires non-final parts of at least 5 MiB, uniform non-final sizes and at most 10,000 parts. The uploader must bind upload identity, object/account ownership, reservation, expected bytes and part completion to authenticated state; the public example is scaffolding without those application guarantees. Cap retries and unfinished parts; resume does not itself validate the upload ID. [Multipart Worker guide](https://developers.cloudflare.com/r2/api/workers/workers-multipart-usage/), [upload limits](https://developers.cloudflare.com/r2/objects/upload-objects/), [R2 API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/).

R2 presigned URLs grant whoever holds the URL the operation until expiry (1 second to seven days). Direct GET/PUT URLs bypass subsequent application session/pause checks. Revoking a Cloud session in D1 does not itself revoke those capabilities, and R2 permission changes can take up to a minute to propagate. Short URL lifetimes reduce exposure; they do not implement immediate revocation. [Presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/), [consistency and IAM propagation](https://developers.cloudflare.com/r2/reference/consistency/).

**Design inference:** Worker-mediated bounded requests offer a place to recheck session generation, account restrictions and transfer pauses on every new request/part/range and before committing an upload. A stream already authorized and sending bytes does not automatically recheck D1. Documentation supplies no guarantee that a pause can retract delivered bytes or synchronously cancel every existing stream. Specify allowed in-flight completion versus cancellation and measure propagation/bytes-after-revocation; do not claim instantaneous interruption. Private responses also need a deliberate cache policy so cached paths cannot bypass current authorization. Avoid long-lived direct credentials/URLs if their lifetime conflicts with the eventual pause/suspension contract.

## D1 atomic operations and the object-store boundary

D1 `batch()` runs prepared statements as a transaction; an actual statement failure rolls back the sequence. Results expose `success` separately from `meta.changes`. A conditional update affecting **zero rows is not a SQL failure**. Putting an account/quota compare-and-set first in a batch does not automatically prevent a later unconditional insert from committing. Dependent statements must enforce the same successful-operation predicate, or another proven SQL construction must turn the invalid transition into failure. Inspecting results only after commit cannot undo earlier writes. [D1 batch semantics](https://developers.cloudflare.com/d1/worker-api/d1-database/), [return objects](https://developers.cloudflare.com/d1/worker-api/return-object/).

The inspected D1 binding source carries `changes` in metadata, submits batch statements together and propagates returned errors; it does not convert a zero change count into an exception. This corroborates the API distinction, not an end-to-end transactional test of a future schema. [D1 binding source at inspected commit](https://github.com/cloudflare/workerd/blob/721cbdbf0a3f8aee2a8f23978b32731a354a5994/src/cloudflare/internal/d1-api.ts).

**Design inference:** registration-at-commit, stale Administrator edits, per-account byte reservations, duplicate uniqueness, Cloud session revocation, first-service-accepted conflicts and deletion-wins rules can be expressed using authoritative SQL predicates, unique operation identities and version checks. A retry must return/reconcile its prior operation result rather than reserve twice. Unknown network outcomes require reconciliation; an HTTP error does not prove rollback. Read replicas require the documented session/primary consistency choices for security-sensitive checks. A D1 session supplies sequential consistency, not a transaction spanning arbitrary Worker awaits. [D1 sessions](https://developers.cloudflare.com/d1/worker-api/d1-database/).

D1 transactions do not include R2 writes. Use an explicitly recoverable reservation/staging/finalization boundary; abandoned ciphertext, retrying cleanup and replacement headroom remain real storage costs. Recheck the latest Storage limit and account restriction when publishing the object reference. An R2 write can succeed while the D1 commit fails, or vice versa. This is an application consistency obligation, not a provider-wide atomic commit. D1's row/BLOB size limit is 2,000,000 bytes and Free database limit 500 MB, supporting operational rows rather than book blobs. [D1 limits](https://developers.cloudflare.com/d1/platform/limits/), [R2 consistency](https://developers.cloudflare.com/r2/reference/consistency/).

## Nightly recovery points and retention

D1 Time Travel is always on: the plan limits are **seven days on Free / thirty days on Paid**, with no extra history/restore fee. Restores overwrite the database in place and cancel in-flight queries; older restore bookmarks remain available. Restoring can revive old sessions, restrictions, counters and deleted-account state. It does not restore R2 objects or establish an application-consistent library snapshot. [D1 limits](https://developers.cloudflare.com/d1/platform/limits/), [Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/).

For seven usable nightly library recovery points, a proposed snapshot must couple a known D1 state/bookmark or export with a manifest of the exact retained ciphertext object generations, sizes and integrity values. R2's `version` metadata is not proof of S3 historical-version recovery; its S3 versioning operations are unimplemented. Keep immutable generations or actual snapshot copies until every referring recovery point expires. A current bucket listing taken alongside a changing database is not a consistent cross-service snapshot. These are design requirements inferred from the independent APIs. [R2 metadata](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/), [S3 compatibility](https://developers.cloudflare.com/r2/api/s3/api/).

Cron Triggers run in UTC and supply scheduled handlers. A configured nightly schedule alone does not prove a completed recovery point or a 24-hour RPO: track verified completion, retry idempotently and detect missed/partial runs. D1 SQL export requires polling and blocks other database requests while running; quantify this availability impact, including authentication/status/deletion, before adopting nightly export as the method. [Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/), [D1 export API](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/export/).

R2 lifecycle deletes are **typically** performed within 24 hours after expiry, with some configuration-transition delays; that is not a strict maximum physical-erasure guarantee. Incomplete multipart uploads default to seven-day expiry. An explicit cleanup/reconciliation process needs deadline headroom, verification and coverage of staging, copies and backup manifests; do not wait until the contractual last instant to request deletion. [Object lifecycles](https://developers.cloudflare.com/r2/buckets/object-lifecycles/).

**Restore-safety requirements inferred from the accepted contract:** preserve a deletion filter outside the database being rolled back, restore offline, filter permanently deleted accounts and expired records before exposing any service, invalidate restored authorization state and reapply current restrictions. The deletion filter must cover the oldest recoverable snapshot without retaining an identifier beyond its original 60-day deadline. Expiry must follow original event/deletion times, not be reset by backup/restore. Keeping a 60-day record in a database with another 30 days of history can retain it for roughly 90 days; similarly copying seven-day security logs into seven/thirty-day backups can violate the seven-day log maximum. A restore filter prevents resurrection but does not erase an over-retained historical copy. A secure storage layout and evidence for absolute expiry across all copies remain necessary.

Workers Logs currently retains three days on Free or seven on Paid. Paid includes 20 million events/month, then $0.60/million; new Workers enable observability by default. R2's opt-in Data Access Logs has seven-day retention but is best effort and excludes HTTP errors >=400. It is not a complete security or accounting ledger. Both products move to Cloudflare Observability pricing on **1 December 2026**, so recheck costs before a pilot crossing that date. Redact secrets, signed URLs, credentials, plaintext and descriptive identifiers; do not copy these logs into longer-lived database snapshots. [Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/), [R2 Data Access Logs](https://developers.cloudflare.com/r2/buckets/data-access-logs/).

Cloudflare Audit Logs v2 lasts 18 months, including control-plane actors and actions. The DPA's twelve-month infrastructure-access logs concern Cloudflare's processing infrastructure, not automatically every application request. Its deletion/return provision applies on termination/completion and includes legal exceptions; it is not an explicit 30-day per-Cloud-EPUB-account purge promise. The privacy policy also describes broader security/business/legal retention. Obtain a precise provider-data inventory and written scope/deletion evidence, or return the incompatibility to the privacy/architecture decisions. Encryption reduces content exposure; it does not prove retention compliance. [Audit Logs v2](https://developers.cloudflare.com/fundamentals/account/account-security/audit-logs/), [DPA](https://www.cloudflare.com/cloudflare-customer-dpa/), [privacy policy](https://www.cloudflare.com/privacypolicy/).

## Spending evidence and boundedness

| Service | Published price / allowance | Bound actually established |
| --- | --- | --- |
| Workers Free | 100,000 requests/day; 10 ms CPU/invocation. | Execution allowance, not continuous essential-operation availability. |
| Workers Paid | $5/month minimum; 10 million requests and 30 million CPU ms included, then $0.30/million requests and $0.02/million CPU ms. No egress charge. | Per-invocation CPU controls bound one invocation, not monthly request volume. |
| D1 Free | 5 million rows read/day, 100,000 written/day, 5 GB aggregate storage; 500 MB/database. | Queries fail after daily quota exhaustion, affecting essential operations too. |
| D1 Paid | 25 billion reads/month, 50 million writes/month, 5 GB included; then $0.001/million read, $1/million written, $0.75/GB-month. | Excess metered; indexed writes add row cost. |
| R2 Standard | 10 GB-month, 1 million Class A and 10 million Class B operations/month included; then $0.015/GB-month, $4.50/million A, $0.36/million B; free direct egress. | Storage and operations continue billing beyond allowance. Units round upward. |

Sources: [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [D1 limits](https://developers.cloudflare.com/d1/platform/limits/), [R2 pricing](https://developers.cloudflare.com/r2/pricing/). Included account allowances must be otherwise unused. Rates do not include tax, fees or separate services.

The earlier baseline's 1 GB live library plus seven full 1 GB snapshots uses 8 GB, before staging, manifests, database exports, dictionary packs and an eighth snapshot under construction. Its assumed 100,000 Worker requests, 10 million database reads and 100,000 writes/month fit Paid allowances. These assumptions explain approximately $5/month, not a maximum. R2 Standard rather than Infrequent Access avoids minimum-duration/retrieval charges. Dictionary cost remains actual hosted pack bytes plus requests/chunks; source archives are not application-pack measurements. [Earlier immutable workload note](https://github.com/A3R0-01/Cloud-Epub/blob/4ff9dea4de5d36f79f8e0b8ef69493c7a719a45b/Docs/research/pilot-hosting-budget.md), [R2 pricing](https://developers.cloudflare.com/r2/pricing/).

An original counterexample from published Paid rates: **27 million billable inbound HTTP invocations/month cost $5 + (27−10) × $0.30 = $10.10**, before CPU, D1, R2, logs, tax or fees. An early transfer-paused response is still an invocation. Budget alerts explicitly notify without capping or pausing usage. Application quotas can constrain authorized R2 activity; they do not alone constrain incoming Paid Worker charges. [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [budget alerts](https://developers.cloudflare.com/billing/manage/budget-alerts/).

A Free Worker gateway with atomic global storage/operation budgets is a conceivable application-level cost-bounding candidate, not a verified provider total cap. It must account for every path: reservations, failed/retried requests, multipart parts, snapshots, dictionary reads, cleanup, Administrator/SDK/S3 access and concurrent in-flight work. A byte allowance alone does not bound tiny/empty object counts or create/delete churn. Service capacity must also cover physically retained deleted objects, staging and backups; this research selects no object-count or transfer quota. Free Worker/D1 exhaustion can still prevent required authentication/status/deletion and backup completion. Moving essential endpoints to another Worker in the same account does not establish an independent allowance. R2 pricing explicitly exempts 401 Unauthorized requests; that is not proof all 403/error requests are free. [Workers limits](https://developers.cloudflare.com/workers/platform/limits/), [D1 quota behavior](https://developers.cloudflare.com/d1/platform/pricing/), [R2 pricing FAQ](https://developers.cloudflare.com/r2/pricing/), [R2 error codes](https://developers.cloudflare.com/r2/api/error-codes/).

Use the provider's actual accounting windows: D1 Free resets at 00:00 UTC, while its Paid included usage resets on subscription renewal. R2 storage billing uses average daily peaks, so temporary overlapping copies affect cost even if later deleted. An application calendar-month counter cannot be assumed to match every provider meter. [D1 billing definitions](https://developers.cloudflare.com/d1/platform/pricing/), [R2 storage billing](https://developers.cloudflare.com/r2/pricing/).

Small static Administrator UI assets can share the service without a separate paid host; direct Static Assets requests have no request/storage charge, but Worker-first authentication/routing adds Worker invocations. A public static shell cannot contain privileged data and does not authorize its API. Static file size remains 25 MiB. Actual dictionary packs exceeding that need a measured split format or separately costed R2 delivery. Avoid adding paid identity, DNS, domain, observability or scheduler services without recalculating the total. [Static Assets billing](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/).

The fixed-price VPS lead from the earlier research remains only an alternative lead if Cloudflare gates cannot close: an annual advertised equivalent is not a verified monthly quote with seven recovery points, retention and final tax. No replacement provider has been validated here. Billing address, applicable tax, payment/foreign-exchange fees, actual account sharing and final order quote cannot be inferred from the user's timezone. They must be established before a final US$10 claim; the hard ceiling has not been waived.

## Measurable gates for later decisions

1. **Security/runtime:** compile the actual candidate dependency graph with pinned compatibility date and versions; run Android/backend interoperability and negative vectors. Measure cold/warm CPU, memory, bundle size, peak concurrent requests, authentication/recovery/second-factor work and secret-free logs. Demonstrate the proposed security parameters under Free or explicitly cost Paid; do not infer safety from toy parameters or a successful import.
2. **Transfers/revocation:** exercise a large encrypted EPUB through streaming/multipart, network loss/resume, duplicate part retries, simultaneous reservations, reduced allowance mid-upload and crash after each D1/R2 step. Record bytes and completion permitted after Cloud session revocation, Administrative suspension and each transfer pause; test existing streams/URLs, new ranges, alternate endpoints and cache paths. The administration/security decisions must accept the measured in-flight semantics.
3. **Atomic behavior:** force zero-row compare-and-set, stale settings changes, closed registration, duplicate operation IDs, concurrent identical EPUBs, deletion races and ambiguous network outcomes. Prove every dependent write respects the winning predicate and retries neither double-charge storage nor resurrect deleted data. Measure SQL scans/index writes and verify primary/session consistency for restrictions.
4. **Recovery/retention:** complete seven nightly recovery points, inject a missed/partial run, measure snapshot age and export downtime, and restore each point with its exact object manifest. Prove the accepted 24-hour RPO, filter deleted accounts before access, invalidate restored sessions, and show original absolute log/backup/deletion-record deadlines across exports, Time Travel, copied objects and external operator artifacts. Obtain evidence for provider-held copies and record categories that application tests cannot inspect.
5. **Budget/essential operations:** enumerate every billable category, bound or measure each path, model 31-day usage plus concurrency/late billing, and test limits without real unbounded billable traffic. Show how authentication/recovery/status/deletion and required backups survive the selected exhaustion policy. Obtain tax/fee/order facts. If this cannot establish the ceiling, keep provider adoption open and research a verified bounded alternative; neither an alert nor a transfer pause closes this gate.

The later architecture and security decisions should consume these findings and measured results. This note resolves the factual research question with explicit gaps; it does not resolve those decisions.
