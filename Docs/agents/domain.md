# Domain docs

## Before exploring

Read GLOSSARY.md at the repo root and relevant ADRs under Docs/adr/.

If these files do not exist, proceed silently. The domain-modeling
skill creates them when terms or decisions are resolved.

## Layout

This repo uses one context:

- GLOSSARY.md contains the domain vocabulary.
- Docs/adr/ contains numbered architecture decision records.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the term or record the
gap for domain-modeling.

## Decisions

If a proposal contradicts an ADR, identify the ADR and explain why
the decision should be reconsidered.
