# Android fixture evidence — 20 October 2026

The previously identified gaps have executable adapter implementations in the throwaway harness. **98/98 final checks pass: focused 27, extended 22, gap follow-up 24, native word/correction 9 and Google TalkBack 16.** The final probe artifacts below record observed results; this is feasibility evidence for the candidate and its extensions, not renderer adoption or a production release guarantee. The initial 45/48 runtime checkpoint is preserved at commit `988996793d551a46102cea8e08de438ae705c58c`.

| Continuous chapters | Native vertical scrolling stays within a chapter; deliberate next/previous swipes and native buttons/list land at beginnings; no boundary wrap. Default engine Previous landed at the prior chapter's end, so activity-level gesture routing through explicit links is required. |
| Exact original destinations | Original node/UTF-16 ranges verify quote and imported-file hash. Distant duplicate occurrences, identical passages, split markup, captions and arrival highlighting survive tested reflow. Generated viewer labels are rejected. Transformed resource lengths/Readium progression are not canonical identity. |
| Regular bookmarks | First-visible text and image destinations are stored as original-content anchors. An image-first-visible setup uses a shortened viewport; full-chapter fit would be invalid setup. |
| Native selection/correction | Native long presses provide selections that the adapter resolves to original-node words, including internal apostrophe/hyphen, composed/decomposed accents, emoji offset, soft hyphen, ligature and split markup. Raw native selection and resolved target are both captured. WebView may highlight only `well` in `well-being`; changing that native range from JavaScript disturbed the menu/handles. A CSS Highlight paints the complete canonical candidate without changing native handle geometry. The Precise bookmark action shows that complete candidate in the accepted confirmation flow, where native Previous/Next word correction and Save preserve the exact adjacent occurrence. Correction moves the visible candidate and Save ends the temporary highlight. This does not claim control of WebView's raw handle geometry; it remains a production UI qualification constraint. The word rule is fixture-specific, not a multilingual policy. |

External SVG, matching picture source, labelled single CSS background and inline SVG open through canvas rasterization; source dimensions and selected picture source are recorded. ## Screen-reader provenance and calibration

Google public TalkBack source commit [`229212fdf5842191d0a93fc95d9ca1423b346866`](https://github.com/google/talkback/tree/229212fdf5842191d0a93fc95d9ca1423b346866), version `TfPu_release_16_2`, was built locally for x86_64. [Reproduction](google-talkback-build.md), [build log](google-talkback-build.log), [external build init script](google-talkback-build.gradle), [APK identity/hash](google-talkback-apk-verification.txt). Build uses Gradle 8.14.3/Microsoft JDK 21.0.12, SDK 36/Build Tools 35 and NDK 21.4.7075529; external init limits ABI to x86_64 and Kotlin JVM target to 17 to match Java. The Google source itself is unchanged. It is a debug source build, not the commercial Google Play Accessibility Suite binary or release certification.

Additional earlier checks use [Backtalk](https://github.com/trypsynth/backtalk), a maintained TalkBack fork, version `TfPu_release_16_2-2026_10_20_0359`, code 70000361, x86_64. [Captured release metadata](backtalk-release.json) and [APK verification](backtalk-apk-verification.txt) match the publisher's asset SHA-256 `1405d5e759a4e47373f902858d99daf4184f751fd8345ef0d0c281d14386a99e`. The dev tag is mutable; that digest identifies the actual downloaded binary. It does not establish an exact corresponding source commit. eSpeak 1.52.0/code 22 supplies TTS ([verification](espeak-apk-verification.txt)). No independent speech-quality/user-usability assessment is claimed.

The suite first calibrates actual raw touch exploration: it must focus the named image without opening it. Raw keyboard Meta+Space then follows the service's real activation path. Read-only API 34 app-process accessibility queries inspect actual focused nodes; they do not inject focus/clicks. Meta+Ctrl+A opens the service-owned Actions menu, raw exploration selects each item, screenshots show selected labels, and resulting image matrices prove execution. [Input-device mappings](input-api35.txt) document this disposable rootable AVD. These helpers are device-specific.

The October 16 API 30/F-Droid TalkBack 2021 captures are superseded for accessibility claims: service binding plus synthetic ADB taps lacked the above calibration, and TTS/service compatibility was incomplete. They do not establish an engine accessibility defect. UiAutomation can suppress services and is excluded from the calibrated suite. Google source [custom-action filtering](https://github.com/google/talkback/blob/229212fdf5842191d0a93fc95d9ca1423b346866/utils/src/main/java/com/google/android/accessibility/utils/AccessibilityNodeInfoUtils.java) explains the system-ID boundary; source execution plus real menu evidence supports the app-resource-ID fix.

## Remaining specification and release limits

1. Meaningful/decorative classification follows explicit metadata in the fixture. Ambiguous/missing/mis-authored semantics, complex/multilayer CSS, external resources/links and unsupported image extraction need explicit product fallback rules. The spike does not choose those rules; [Define ambiguous-image handling and unsupported-resource fallbacks](https://github.com/A3R0-01/Cloud-Epub/issues/19) now owns that HITL decision and blocks the final specification.
2. Import validation, malformed/hostile EPUB and SVG, giant assets/memory budgets, extraction errors and a broader corpus require production validation. Never expose this trusted-fixture debug bridge to untrusted books.
3. Shipping Android/WebView/TalkBack versions, physical-device testing, book languages/segmentation and font selection/licensing are still support/release decisions. The experimental min SDK is not a commitment; the API 34 inspector is a diagnostic tool.
4. Earlier cold-start diagnostic timeouts exposed a page-callback/adapter-readiness race. The harness now consumes the adapter ready signal, serializes restoration, and allows 90 seconds for diagnostics. Startup performance remains unqualified and must be profiled before adoption.
5. Production security, encrypted storage, synchronization/conflicts, dictionary, complete bookmark management and lifecycle/recovery behavior belong to later architecture/implementation work. No production app/backend, PR, merge, deployment or stack adoption was made.

Cleanup review retains lifecycle/selection/bridge callbacks, substantive anchor validation, native focus ownership, bitmap/gesture resource lifetime and viewer stages. Obsolete unsuccessful DOM-focus/web-dialog experiments were removed; extra diagnostic captures remain outside git. Compiler/offline assembly, JavaScript/PowerShell syntax, EPUBCheck and final diff checks accompany the runtime artifacts.
